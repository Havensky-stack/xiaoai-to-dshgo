# Agent 手机 · 计划书 v2

> 2026-11-22 修订。目标从「单 APK 自足」改为「**dsh-go 作引擎 + LSPosed 模块接管小爱**」

## 一、目标

**一句话**：一台已 root 的小米手机，装 **dsh-go** 和 **一个 LSPosed 模块**，
在 dsh 里授权一次，就完成对小爱同学的替换——手机变成 Agent 手机：
你说话，dsh 接住，需要操作手机时在**另一块虚拟屏**上干活，不抢你的前台界面。

**交付物**

| # | 交付物 | 说明 |
|---|---|---|
| 1 | LSPosed 模块 APK | 接管小爱的助理入口与语音结果，转给 dsh-go |
| 2 | dsh-go 插件 | 胶囊/面板 + `vdisplay_*` 后台屏工具 + 语音状态 |
| 3 | 虚拟屏运行时 | 基于 scrcpy-server 的 VirtualDisplay，由插件管理 |

**不再需要的**：独立助理壳 APK（不再自建语音栈）、自研唤醒引擎接入。

## 二、架构

```
         ┌──────────── 小爱（com.miui.voiceassist）────────────┐
         │ 唤醒词引擎（libwakeup-engine / flexkws）             │
         │ ASR（com.xiaomi.mibrain.speech）                     │
         └───────────────────┬──────────────────────────────────┘
                             │ LSPosed 模块 hook：
                             │ ① 识别结果 → 不再走小爱 NLU
                             │ ② 入口（长按/手势）→ 启动 dsh-go
                             ▼
                    ┌──────────────────┐
                    │   dsh-go（引擎）  │  ← 你的授权、模型、工具
                    └────────┬─────────┘
                             │
              ┌──────────────┴───────────────┐
              ▼                              ▼
     ┌─────────────────┐            ┌──────────────────┐
     │ 语音回复（TTS）  │            │ dsh-go 插件       │
     │ 系统 TTS 播报    │            │ vdisplay_* 工具   │
     └─────────────────┘            └────────┬─────────┘
                                             ▼
                                  ┌──────────────────────┐
                                  │ VirtualDisplay       │
                                  │ 720×1592 / 独立焦点  │
                                  │ 不抢主屏、不抢输入法  │
                                  └──────────────────────┘
```

**分工原则**：小爱只当"耳朵"（唤醒 + ASR），dsh-go 当"大脑"，插件当"手"，虚拟屏当"工作台"。

## 三、为什么这条路更稳

| 对比项 | 旧方案（单 APK 自建语音栈） | 新方案（dsh-go + LSPosed） |
|---|---|---|
| 唤醒词 | 要自己接引擎/训练模型 | **复用小米现成的**，只需 hook |
| ASR | 要自建或依赖系统接口 | 复用小爱/小米 ASR |
| 大脑 | 要内嵌 node 引擎 | **现成的 dsh-go** |
| 插件生态 | 要自己做兼容 | **天然兼容** |
| 升级维护 | 跟着上游改 | 只维护模块，dsh-go 自己升级 |
| 体积 | ~100MB+ | 模块几百 KB + 插件几十 KB |

## 四、现状盘点（已验证）

| 能力 | 证据 |
|---|---|
| 抢助理角色（壳形态） | `io.github.dsh.voice` 持 `ASSISTANT` |
| 语音结果可被 hook 截获 | XiaoaiBridge 抓到「你好啊」 |
| 签名权限可绕过 | `DSHPERM: granted …EXTERNAL_AGENT uid=10055` |
| 小爱 CLI 可调用 | `session.open`、`ping`、`auth.status` 均返回 |
| 虚拟屏权限具备 | `ADD_TRUSTED_DISPLAY: granted=true` |
| 3D 渲染支持 | `vendor.display.vds_allow_hwc=1` |
| dsh-go 可被 SEND 唤起 | `dsh_app/.share.ShareActivity` 带文本 |
| 逆向环境 | jadx、Ghidra 12.2(arm64 自编译)、Craft Anything |

**未验证**：dsh-go 是否有可用的 TTS/语音播报；虚拟屏在 Android 17 的实际建屏表现；小爱被封印后唤醒是否仍工作。

## 五、阶段计划

### P0 · 打通「小爱听见 → dsh-go 收到」

| 项 | 内容 |
|---|---|
| 做什么 | LSPosed 模块 hook 小爱的识别结果出口（`agent.submit` 或 ASR 回调），把文本用 `ACTION_SEND` 交给 dsh-go；同时抑制小爱自身的 NLU 响应 |
| 验收 | 对手机说「今天天气怎么样」，dsh-go 里自动出现这句文本的对话 |
| 风险 | 小爱的 NLU 与界面耦合紧，抑制可能连带影响识别流程 → 退路：只转发不抑制 |

### P1 · 语音回复

| 项 | 内容 |
|---|---|
| 做什么 | dsh-go 的回答用系统 TTS 播报；加一个开关（静音/只播报短答） |
| 验收 | 说完一句，能听到 dsh-go 的回答 |
| 风险 | dsh-go 侧如何把回答回传给模块 → 用广播或本地 HTTP 回调 |

### P2 · 后台屏插件

| 项 | 内容 |
|---|---|
| 做什么 | 安装/自研 dsh-go 插件，提供 `vdisplay_start/launch/shot/text/tap/stop`，用 scrcpy-server 建虚拟屏 |
| 验收 | 主屏放视频，AI 在虚拟屏完成「打开设置 → 找到 WLAN → 读出状态」 |
| 风险 | Android 17 的 `createNewVirtualDisplay` 行为变化；`FLAG_SECURE` 页面截不到 |

### P3 · 封印小爱与入口改绑

| 项 | 内容 |
|---|---|
| 做什么 | ① 让小爱不出声、不弹窗；② 长按电源键/手势改为启动 dsh-go 语音入口 |
| 验收 | 重启后，「小爱小爱」唤起的是 dsh 的对话；小爱不再抢答 |
| 风险 | HyperOS 把长按键绑死在 SystemUI，需 hook 手势层；唤醒词依赖小爱进程存活 |

### P4 · 一键化与文档

| 项 | 内容 |
|---|---|
| 做什么 | 模块首次运行引导：检测 root/Vector、授权、安装插件、校准唤醒延迟；写清安装步骤 |
| 验收 | 另一台同型号手机照文档能在 10 分钟内跑通 |
| 风险 | 不同机型差异（小米/红米/HyperOS 版本） |
