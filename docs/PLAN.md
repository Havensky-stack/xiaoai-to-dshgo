# Agent 手机 · 计划书 v3（完美接替版）

> 2026-11-22。目标：**完美接替小爱**——系统所有入口都通向 dsh-go，小爱退化为纯“外设”。

## 一、核心判断：必须借壳

小米系统里这些入口是**按包名 `com.miui.voiceassist` 硬编码**的：

| 入口 | 谁在点名 |
|---|---|
| 长按电源键 / 手势 | SystemUI / HyperOS |
| 「小爱小爱」唤醒 | 常驻唤醒引擎 |
| 输入法语音键 | `IVoiceIMInterface` 调用方 |
| 蓝牙耳机语音键 | 蓝牙系统 App |
| 锁屏唤起 | 锁屏 / 安全中心 |
| 负一屏、超级岛 | 系统桌面 |
| 设置里的 AI 页 | 设置 |

新 App 顶替 `ASSISTANT` 角色**接不到以上任何一个**。

**结论**：完美接替 = **保留小爱包，劫持其全部对外行为**。
小爱在系统眼里仍是助理，实际只提供两样东西：唤醒词引擎与 ASR；其余全部由我们接管。

## 二、接替矩阵

| # | 入口 | 现状 | 接替方式 | 优先级 |
|---|---|---|---|---|
| 1 | 助理角色（AssistInteractionService） | 小爱持有 | 模块 hook，会话开启后拉起 dsh 语音界面 | **P0** |
| 2 | 语音识别结果 | 小爱 NLU 消费 | hook 结果出口，转 dsh，同时抑制小爱应答 | **P0** |
| 3 | 小爱自身应答（声音/弹窗/悬浮窗） | 正常响应 | 模块抑制（不渲染、不播报） | **P0** |
| 4 | `SPEECH_QUERY`（第三方投查询） | 小爱处理 | 模块拦 Service 调用，转 dsh | P1 |
| 5 | `PUSH_QUERY` Activity | 小爱界面 | 模块拦启动，改起 dsh | P1 |
| 6 | 输入法语音键（`IVoiceIMInterface`） | 小爱 | 模块拦 Binder 调用，转 dsh | P1 |
| 7 | 蓝牙耳机语音键 | 小爱 | 拦广播/绑定，转 dsh | P2 |
| 8 | 锁屏唤起 | 小爱 | hook 锁屏入口，转 dsh | P2 |
| 9 | 负一屏 / 超级岛卡片 | 小爱 | 拦 `island` 广播与 Activity，转 dsh 状态 | P2 |
| 10 | 快捷方式 `ACTION_SHORTCUT_START` | 小爱 | 改起 dsh | P3 |
| 11 | OSBot 外部接口（agent/tool/CLI） | 小爱 | 按需接：让 dsh 的工具对小爱生态可见 | P3 |
| 12 | 语音播报 | 小爱 TTS | 改用系统 TTS（dsh 的回答） | P1 |
| 13 | 后台操作手机 | 小爱无障碍 | dsh-go 插件 + 虚拟屏 | P2 |

## 四、阶段计划

### P0 · 最小可用闭环（借壳成立）

| 项 | 内容 |
|---|---|
| 做什么 | 模块 hook 识别结果 → `ACTION_SEND` 给 dsh-go；抑制小爱自身应答；助理会话改为拉起 dsh |
| 验收 | 长按唤起 → 说「今天天气」→ dsh 收到文本并回答（屏幕上），小爱**不出声不弹窗** |
| 风险 | 小爱 NLU 与 UI 耦合；抑制可能影响识别流程 → 退路：只拦结果不拦 UI |

### P1 · 入口与语音回复

| 项 | 内容 |
|---|---|
| 做什么 | 系统 TTS 播报 dsh 回答；接 `SPEECH_QUERY`、`PUSH_QUERY`、输入法语音键 |
| 验收 | 输入法按住说话 → dsh 收到；回答能被念出来 |
| 风险 | Binder 拦截需在正确进程与时机 |

### P2 · 硬件入口与后台屏

| 项 | 内容 |
|---|---|
| 做什么 | 蓝牙耳机键、锁屏唤起、超级岛；装/写虚拟屏插件，AI 在后台屏操作 App |
| 验收 | 耳机键唤起 dsh；主屏放视频时 AI 在虚拟屏完成「打开设置→读 WLAN 状态」 |
| 风险 | 耳机键在系统蓝牙 App 里，需另找 hook 点；虚拟屏在 Android 17 的表现待测 |

### P3 · 生态面与打磨

| 项 | 内容 |
|---|---|
| 做什么 | 快捷方式、OSBot 工具互通；模块内的一键配置页（检测 root/Vector、授权、日志） |
| 验收 | 小米自家入口（负一屏、设置 AI 页）也能落到 dsh |
| 风险 | 各家入口实现不同，需逐个适配 |

## 五、可验收的“完美”清单

模拟一个用户从买到机到日常使用：

1. 长按电源键 → dsh 语音界面（不是小爱）
2. 说「小爱小爱」→ dsh 响应
3. 锁屏说一句 → dsh 响应
4. 输入法语音键 → dsh
5. 蓝牙耳机键 → dsh
6. 第三方 App 投 `SPEECH_QUERY` → dsh
7. 负一屏/超级岛 → dsh 状态
8. 小爱全程**不出声、不弹窗、不抢焦点**
9. 回答能被念出来，也能只看屏幕
10. 「帮我关掉 WiFi」→ 后台屏自证执行完成，主屏不被打扰

十条全中，才算“完美接替”。

## 六、最大风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **小爱升级换实现** | 我们 hook 的是具体类/方法，升级后偏移 | 用「行为特征」定位（字符串、接口名）而非硬编码类名；模块内置自检 |
| **HyperOS 收紧** | 签名权限校验、SELinux 收紧 | 已有 uid 级绕过方案，可迁移 |
| **系统级入口藏在别处** | 某些入口由 SystemUI 直接拉起 | 逐入口实测，矩阵里补 |
| **唤醒词依赖小爱进程** | 抑制过度可能让她停止服务 | 只抑制“输出”，不动“输入链路” |

## 七、需要你拍板

| # | 问题 | 建议 |
|---|---|---|
| 1 | 小爱保留到什么程度 | **只留唤醒+ASR，其余全抑制**（推荐） |
| 2 | 回答形式 | 屏幕文字 + 可选 TTS 播报 |
| 3 | 后台屏 | 先用社区 `dsh-go-second-screen`，跑通再考虑自研 |
| 4 | 模块兼容范围 | 只保当前 HyperOS 版本，还是尽量向前兼容 |

## 八、root 带来的简化（v3.1 补充）

有 root 就不该硬碰硬去 hook。原则：**能改状态的用 root，必须拦逻辑的才 hook。**

### 8.1 可用 root 直接做的事

| 能力 | 命令/方式 | 替代掉的 hook |
|---|---|---|
| 冻结小爱的指定组件 | `pm disable-user --user 0 com.miui.voiceassist/.XxxActivity` | 抑制应答的 hook |
| 授权签名权限 | 改 `/data/system/packages.xml` 补 `<perms>` | system_server 权限 hook |
| 开机自启服务 | KernelSU `service.d` 脚本 | 前台服务保活 |
| 建虚拟屏 | root 直接 `app_process` 跑 scrcpy-server | **免 adb、免 tcpip** |
| 注入触摸 | `input -d <displayId> tap x y`（Android 11+） | scrcpy 控制通道 |
| 改系统属性 | `resetprop` | 各种开关 hook |
| 强杀/重启进程 | `am force-stop` / `kill` | 状态清理 hook |
| 读任意文件 | 直接读 `/data` | 提权相关 hook |

### 8.2 仍然只能 hook 的两件事

1. **识别结果的实时截获**——文本出现在内存里，没有落盘，只能 hook 或 hook 其回调
2. **入口的运行时重定向**——长按键被 SystemUI 点名拉起小爱，必须在拉起时改道

其余全部可以“改状态”解决，比 hook 稳定得多。

### 8.3 用 root 重排 P0

| 原计划 | root 版做法 |
|---|---|
| hook 抑制小爱应答 | **`pm disable-user` 停用小爱的对话/播报组件**，只留唤醒与 ASR 服务 |
| 改 ASSISTANT 角色 | 保留小爱持角色，模块只改“会话开启后干什么” |
| 后台屏依赖 adb | **root 直接建屏**，省掉 adb tcpip 与配对 |
| 前台服务保活 | KernelSU `service.d` 开机拉起 |

### 8.4 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 停用组件导致其他入口崩溃 | 某些系统页会 bind 小爱组件 | 逐个停用、逐个验证；记录回滚命令 |
| 改 `packages.xml` 写坏 | 可能无限重启 | 先备份；优先用 KernelSU 的 priv-app overlay 替代 |
| root 权限面扩大 | 模块本身成为高价值目标 | 模块只做最小操作，不常驻特权 shell |
